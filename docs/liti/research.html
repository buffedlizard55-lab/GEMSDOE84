4. Next steps and limitations (for the next session)

  1. Make the holdout gate fair (IR-84-04): rebuild the incumbent recipe from a field trained on the visible catalogue only, or have the owner adopt the repo-grouped live-score CV as a second, pre-registered instrument. As things stand the gate favours catalogue-trained fields.
  2. Owner ruling on IR-84-03: dense registry rasters (e.g. a 5-px lattice) make the literal 70 % overlap rule unsatisfiable for every lane. The fix belongs in the shared template (60GEMSDOE), which lanes cannot push to.
  3. Organizer receipts: copy submission IDs and scores from the submission page so OWNER-REPORTED rows become ORGANIZER-CONFIRMED. The inversion is only as good as these labels.
  4. Use LITI as a prior, not a generator: its strongest, cross-validated terms (negative catalogue density, near-fault exclusion, terrain-line and basement-gradient enrichment) can re-weight any lane's field before emission. Every lane can apply it as a cheap pre-screen before spending a slot.
  5. Data blocked here: USGS ComCat hypocentres and focal mechanisms (H84-D) and InSAR/optical products for the 2020 Monte Cristo Range rupture (H84-E). A GitHub Actions runner can fetch them (it has open internet); this sandbox cannot.
  6. Compute: a 1 m-LiDAR deep detector needs a GPU, which this environment does not have.
