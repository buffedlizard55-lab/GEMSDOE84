# GEMSDOE84 — GEMS Prize research and submission workbench

> **Persistent project brief — read before every work session.** Build an auditable, scientifically defensible system for discovering unmapped faults indicative of geothermal resources in the DOE GEMS / GeoDAWN study area. Maximize the probability of a genuinely useful result; own the outcome from data provenance through evaluation and valid submission. Do not claim an improvement, invent evidence, or spend a competition slot without the prescribed holdout gate. Make a valid submission GeoTIFF obvious and easy to download only after it has passed automated validation. Preserve research, assumptions, irregularities, and official-source links so the work is useful and reproducible beyond this session.

## Operating rules

1. **Stay in the selected experiment lane.** Before surface construction and again after final emission, compare the candidate against available registry rasters. If absolute rank correlation exceeds `0.90`, or more than `70%` of emitted dots fall within `3 px` of any one registry raster's dots, record a duplicate and stop. Do not silently switch methods.
2. **Reuse shared tools; do not fork or rebuild them.** Use the template's cached feature stack, `evaluate_holdout.py`, and `submission_writer.py`. Hold out whole fault segments with a buffer; derive catalogue-dependent features from visible faults only; mask visible faults pixel-exactly; evaluate pooled DTI with `alpha=0.2`, `beta=0.8`, and a `300 m` triangular kernel. If a shared tool is defective, fix it in the shared template and report the fix.
3. **Separate evidence classes.** A measured holdout value must be reported as **HOLDOUT-DTI**, with evaluator version, number of withheld positives, and `95% CI`. An external competition score may be called **ORGANIZER-CONFIRMED** only when copied from a submission-page receipt. Projections are not scores. Do not infer a score from a project page or a leaderboard row.
4. **Run a leakage canary.** Test each feature by itself on the holdout before trusting a combined result. AUC above `0.90` is leakage until demonstrated otherwise.
5. **Use a final run card.** Record hypothesis, mechanism, named non-fault mimic, HOLDOUT-DTI and confidence interval, registry correlation/overlap, raster SHA-256, validator result (finite values in footprint, range `[0,1]`, CRS/shape/transform), submission identifier and a note of at most `140` characters, and verdict `promote` or `negative`.
6. **Respect the experiment and time budget.** Stop at three experiments or two hours, whichever comes first. Do not select or promote a submission here: selection is a separate step subject to the live weekly submission cap.
7. **No fake deliverables.** Never package an arbitrary or copied raster as a new submission. If required data, the shared evaluator/writer, provenance, or uniqueness check is missing, report the blocker and do not represent a file as ready to submit.

## What the official materials establish

The competition is a fault-mapping task, not direct geothermal-vent detection. The official description says the prediction target is geological faults; test labels include expert-identified faults missing from the existing public fault database. Faults can be associated with fluid pathways, but that does not make every detected lineament a geothermal system. The official metric is a distance-weighted Tversky index with `alpha=0.2`, `beta=0.8` and a triangular kernel with `300 m` support. The official submission specification requires one float32 prediction layer, values in `[0,1]`, the training raster's CRS, resolution and bounds, and null/NaN outside the bounds.

The official data page redirects to account login. This checkout has no competition data and no DrivenData credentials; it is therefore not possible here to download the gated training feature stack, labels, sample submission, or DEM link table. Do not attempt to bypass that access control or ask for credentials in chat.

## Forensic answer: the reported GEMSDOE32 H33 result

The submitted H33 filename and value quoted in the request are not independently established by the evidence available in this checkout. The GEMSDOE32 project page presents H33-2-B2 as a candidate and explicitly distinguishes projected/modelled values from an organizer score; a separate GEMSDOE83 page calls a value for H33 organizer-confirmed but does not itself provide the DrivenData submission-page receipt required by this project's evidence rule. These statements conflict in evidentiary status. No receipt or original submission bytes are present here. **Therefore, this repository cannot confirm the H33 score, its exact raster, or that it was the highest-scoring submission.**

A plausible mechanism, not a verified explanation of that particular score, follows from the official metric: predictions near held-out fault pixels receive distance-weighted credit, while prediction mass away from the hidden faults incurs a false-positive penalty. Thinning a broad candidate surface can improve DTI if it removes low-credit predictions while retaining high-credit coverage. That is a testable metric explanation—not proof that H33's thinning caused its reported result. A public-catalogue hide-and-recover holdout also cannot establish that a candidate finds genuinely unmapped faults; it measures recovery of withheld catalogue faults and is only a screening instrument. The requested claim of beating any quoted score is not supportable without the exact candidate, the shared spatial holdout, and a verifiable organizer receipt for the comparison artifact.
